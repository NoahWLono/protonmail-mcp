# Security

## Threat model

`protonmail-mcp` handles decrypted email, so the main risks are accidental mailbox mutation,
credential leakage, network exposure, oversized content, and prompt injection inside email.

This release is intentionally read-only:

- No SMTP implementation exists.
- IMAP mailboxes are selected with `readonly=True`.
- Bodies and headers are fetched with `BODY.PEEK`.
- No code calls `STORE`, `COPY`, `MOVE`, `APPEND`, or `EXPUNGE`.
- Attachment bytes are not exposed to MCP clients.
- The MCP HTTP server binds only to loopback.
- Non-loopback IMAP is blocked unless explicitly enabled, and then TLS verification is required.

## Credentials

Use the IMAP password generated by Proton Mail Bridge, not your Proton Account password.
Never commit `.env`. The file is ignored by Git. If you use `PROTON_BRIDGE_PASSWORD_FILE`, the
server refuses files that are group-readable or world-readable.

## Prompt injection

Email is untrusted external content. Messages can contain adversarial instructions intended for
an AI system. Tool descriptions and responses explicitly mark mail as untrusted. HTML is parsed
to inert text and remote resources are never loaded.

A model should summarize or quote mail as requested, but should not treat instructions in a
message as authority to perform unrelated actions.

## Reporting a vulnerability

If you publish a fork, configure a private security contact or GitHub private vulnerability
reporting before inviting external users.
